# 2025 MCM C 题 Codex 执行计划书

版本：v1.0；日期：2026-10-09；项目位置：`C题_Codex独立项目`。

## 1. 目标与本轮范围

目标是依据本地官方题目和提供的数据，完成一套能重复计算、能用历史结果检验、能覆盖各子问题的奥运奖牌分析，并形成代码、结果、图表及论文。

**本轮完成独立项目和执行书；实际数据清洗、建模、预测和论文写作尚未开始。** 本文出现的算法、文件和图表为后续任务，不代表已实现或已有结果。难度不通过堆叠复杂算法解决，模型必须通过历史回测证明其价值。

## 2. 执行边界

1. 模型和数据分析只使用题目提供的 5 个 CSV。不得将外部 GDP、人口、运动员实时成绩、博彩预测或外部 2028 项目数据加入模型。
2. 外部资料只可用于背景和结果解释，逐条注明来源；关于教练的背景资料不能偷偷变成新增训练样本或未披露的模型输入。
3. `source/` 与 `data/raw/` 作为固定输入；处理结果另存 `data/processed/`，每次重要阶段前检查输入哈希。不得修改上级真题目录。
4. 文件、运行环境及输出均放在本项目中；优先使用项目内虚拟环境，避免改变系统 Python。若当前环境无法安装需要的包，记录原因并检查可用替代环境，不把环境失败当作模型失败。
5. 模拟数据、未来假设、估计结果和原始观测应分别标记。正文数字来自保存的计算结果，不手填“合理数字”。
6. 不能保证某个算法最优或某个奖项；目标是证据充分、问题覆盖和可重复运行。

2. 配置项目内 Python 环境，安装并记录实际可用的统计和绘图库版本。先验证一个最小回归和中文图形导出，避免直到报告阶段才发现依赖 / 字体问题。
3. 设置随机种子、路径与日志；使用相对项目根目录定位输入，避免依赖个人机器的硬编码路径。

## 7. 阶段 1：数据审计与清洗

**执行任务**

1. 识别各 CSV 编码、缺失、重复、空白 / 不换行空格、特殊符号。读取后记录行数及字段，不靠猜测自动忽略异常。
2. 建立代码与名称映射。使用提供数据内部的名称、Team、主办信息和重叠关系，保存需要判断的条目；不要按 Team 连字符一律截断。
3. 对历史国家与现在国家、混合队、难民队、中立队等给出处理规则。默认不强行把前苏联等历史奖牌分摊给当前国家；选定近现代主要训练窗并说明理由，长历史用于附加验证。
4. 以奖牌表为国家总量基准，检查 Gold + Silver + Bronze = Total、非负整数、同一代表队届次重复等。错误不能静默覆盖。
5. 由参赛表补入“参赛但未获牌”的样本；没有参赛记录的国家不直接补成零奖牌。某届参赛名单不可在回测中提前使用。
6. 运动员表用于参赛和项目结构，团体奖牌按国家、年份、项目、队伍与奖牌类型等建立候选去重规则，并逐项目核对。发现同一国家同一赛事同色多牌、并列名次或特殊历史记录时保留异常说明。
7. 国家—项目奖牌汇总若不能完全复现官方奖牌表，应说明差异，不强行调数；无法可靠恢复奖牌数的项目可用获奖参赛记录等代理，但需改名并降低结论强度。
8. 项目表特殊标记不能一律转为 0；1906 等特殊届次与取消项目按字典记录口径。总计行与分项行不能重复相加。

**输出**：数据审计报告、映射表、国家届次表、项目表、异常 / 缺失清单。

**验收**：关键连接没有不明的大量丢失；原始输入未变；官方国家奖牌口径保持；零奖牌与未参赛区分清楚；无法解决的异常可追踪。

## 8. 阶段 2：特征、基线与时间回测

**执行任务**

1. 默认用近现代连续多届做主分析；具体起点由审计决定并记录，不为追求好结果反复挑选测试届。
2. 构造仅在预测时可获得的特征：上一届 / 最近几届金牌总牌、过去趋势、历史参赛规模、过去项目结构、已知主场指示和过去项目机会。
3. 对 2028 年可直接使用已提供主办信息；参赛人数、参赛国家、未来项目数均不是已知量，不可使用实际未来数据。
4. 建立上一届延续和最近数届加权平均两种简单基线。窗口、权重仅在训练 / 内部验证中选择。
5. 建立滚动时间切分，例如预测 2008、2012、2016、2020、2024，每次只使用此前届次。年份按数据标记，2020 届不因实际举行年份变化而错误连接。
6. 将 2024 作为尽量少反复调参的最终历史检查；其余切分用于模型选择。每个切分重新拟合缩放、缺失填补、特征筛选和参数。
7. 保存每届各代表队预测与实际，并计算 MAE、RMSE、计数模型合适的预测评分；金牌与总牌分别报告。分强队、中间队、零 / 少牌队检查，避免总体结果掩盖小国错误。

**输出**：特征字典、时间切分配置、基线结果与回测表。

**验收**：每个特征的最晚来源年份早于目标届；未来主办信息单独标明为何可知；没有随机拆分届次或使用目标届实际参赛人数；基线能完整计算。

## 9. 阶段 3：主模型与不确定性

**推荐路线**

先以小规模、可解释的计数模型为主，不默认使用深度学习。

1. 用 Poisson 作为计数模型起点，检查误差与过度离散；再比较负二项模型。
2. 为保证金牌与总牌相容，优先考虑“先预测总牌 T，再预测金牌占比 p，并模拟 G | T”的联合方案，例如二项分布；金牌占比参数用历史数据估计，小样本国家适当收缩。金牌占比需验证，必要时比较更能容纳波动的分布。
3. 如果少牌 / 零牌队表现差，比较“获牌概率 + 获牌后数量”的两阶段模型；正数阶段需满足正计数条件，不能把普通计数模型随意冒充截断模型。
4. 仅在回测发现必要时比较一个树模型，并限制规模；不可把算法越多当作结果越强。
5. 用实际回测选择模型，或形成经验证的组合。复杂模型没有稳定改善时保留基线 / 简单模型，并解释。
6. 通过预测分布模拟或合理的重采样生成未来结果。区分参数不确定性、未来随机波动、未来特征情景和模型选择误差；不能把回归系数置信区间当作奖牌预测区间。
7. 固定主报告为 95% 预测区间，同时检查历史覆盖率和区间宽度；样本有限时报告实际覆盖，不声称已精确校准。重采样保留国家 / 届次结构，不把相关行当作完全独立样本。
8. 检查每次模拟与每张结果表均满足非负整数、G ≤ T。区间可以出现 0；点预测的统计量和展示取整方式应说明。

**输出**：模型公式、拟合配置、模型比较、预测区间验证、主模型选择理由。

**验收**：有基线、有滚动回测、有区间覆盖和宽度；任何模型优势来自保存的结果；约束通过；收敛失败和异常国家被记录。

## 10. 阶段 4：2028 奖牌与首次获牌

### 10.1 2028 奖牌表

1. 明确预测代表队范围。先采用 2024 参赛代表队集合做基准，逐条处理特殊队；这只是未来参赛情景，不是已知 2028 名单。
2. 对历史参赛但 2024 未参赛的未获牌代表队建立扩展参与情景，避免把“首牌候选”静默限制成一个集合。
3. 未来参赛规模从历史预测或设置保守 / 基准 / 扩张情景；记录方法。主办信息可从提供表直接获得。
4. 由于没有 2028 项目列，默认采用 2024 项目结构作为明确标注的基准，并加入基于提供项目数据的机会扰动；绝不把情景命名成“真实 2028 项目”。
5. 输出金牌与总牌、95% 预测区间、2024 实际值、差值及 P(2028 大于 / 小于 2024)。排序规则明确；不能将点排序等同于有把握的名次。
6. 检查总奖牌与项目机会量级。金银铜并列、每项多铜牌等使总牌不是简单 3 × 项目数；若采用总量约束，必须说明口径和适配规则，重算所有区间，不事后只缩放点预测。

### 10.2 首次获牌

1. 首牌定义为“在提供的夏季奥运历史数据与明确代表队延续规则下首次获牌”；不得据此推断冬奥历史。
2. 对候选 i 计算获牌概率 p_i；区分“若参赛则获牌概率”与“考虑参赛概率后的无条件概率”。未来参与假设与奖牌模型保持一致。
3. 预计首次获牌数量为各候选概率之和；模拟整数数量分布，输出区间和最可能数量，以及相关概率。期望值可以是小数。
4. 若为了简化假设各国独立，应披露并用共享机会 / 共同变化情景检查。不得一边强调全球奖牌竞争一边无说明地当作完全独立。
5. 使用历史届次的未获牌集合回测，检查概率校准及实际首次获牌数量是否落在预测范围；每届候选状态只能基于此前历史。

**验收**：所有预测都有情景和区间；候选集合可复核；首牌数量分布归一化；概率在 [0,1]；机会总量与跨国依赖的限制说明完整。

## 11. 阶段 5：项目机会、主场与教练证据

### 11.1 项目结构

1. 建立国家—运动项目优势矩阵，并区分“奖牌多”与“每个机会表现强”；项目 / 分项 / 小项不能混用。
2. 用仅来自历史的优势与赛事数量构造机会指标，比较加入该指标前后的回测，检验它是否有解释或预测价值。
3. 根据提供数据做项目机会增减情景，重算各国结果，解释哪类国家受益或受损。
4. 主场总体效果与项目选择关联分别讨论；主场效应、主办国选择和运动员投入可能同时发生，不能把它们完全拆分的假设当作事实。

### 11.2 名教练效应与三国建议

1. 原始数据没有教练姓名和任职时点，先寻找国家—项目的持续改善、结构变化或异常残差，作为候选证据。
2. 控制数据中可获得的主场、参赛规模和机会变化，并检查改善是否由单届极端值或其他项目变化造成。
3. 候选残差改善可以给出“与教练等因素相容的变化幅度”，不能直接等于教练净因果贡献。对无法识别的贡献给出情景范围或明确不可识别。
4. 外部教练背景仅用于解释和引用；本项目默认不建立依赖新增外部教练记录的因果面板。若以后研究范围需要改变，先明确与题目数据限制的关系。
5. 从数据支持的候选国家中选择三个，说明项目短板 / 潜力和推荐理由；基于已声明的假设估计投资后奖牌变化，并给敏感性范围。
6. 没有预算、工资等数据时，不捏造教练投入金额或精确投资回报率。建议可先讨论相对优先级和条件收益。

**验收**：国家 / 项目选择有数据依据；回测与情景分开；关联、异常变化、因果效果三种表述不混淆；三个国家都有项目建议与带假设的影响估计。

## 12. 阶段 6：原创洞见、稳健性与图表

1. 从已得到结果中挑选至少一项可检验洞见，例如优势项目集中度和成绩波动、参赛规模的边际收益、项目变化风险。只把得到证据的候选写成结论。
2. 做主要特征消融：移除主场、参赛规模、项目机会，观察回测变化，不只看拟合优度。
3. 改变历史窗口、特征权重、参与情景、项目情景和特殊队处理，报告是否改变推荐。
4. 检查随机模拟稳定性。增大抽样数后关键结果应趋于稳定；模拟次数先设可控值，再按误差检查决定，不为了“精确”无限增加。
5. 从结果表生成图形，图上注明单位、年份、样本 / 代表队范围和情景；正文引用与图表一致。

优先图表清单：数据审计 / 覆盖图、模型回测对比、实际—预测图、区间覆盖与宽度、2028 前列代表队区间、改善 / 下降概率、首牌概率和数量分布、国家—项目热图、项目机会情景、教练候选变化、敏感性图。

**验收**：洞见有数据支持；图形来自保存的结果；未只展示有利案例；敏感性结果与推荐一致，结论不稳时如实说明。

## 13. 阶段 7：论文与最终交付

1. 先写中文技术说明，固定口径、模型、结果、局限和建议，再整理英文论文，避免翻译时改变数字或结论强度。
2. 默认采用可编辑 LaTeX 源文件，生成后在 Codex 内置编辑器打开并检查编译诊断；最终 PDF 的导出另行验证，预览成功不能替代实际 PDF 文件交付。
3. 英文正文结构建议：一页 Summary Sheet、目录、问题重述、假设与数据、模型与回测、2028 预测及首牌、项目与教练、原创洞见、敏感性、优缺点、结论与参考文献。
4. 按本题原文安排主体不超过 25 页，AI 使用报告不计入该限额；C 题未要求另写备忘录。图表有页数预算，但最终按实际阅读质量调整，不写满页数凑篇幅。
5. 建立 AI 使用记录，按实际使用填写，核对 2025 题目所指政策。不得替团队或指导老师编造身份、控制号或声明。
6. 把每条核心结论链接到计算表、图或来源。扫描“证明、必然、精确、全部、最优”等表达，删除超出证据的断言。
7. 实际执行统一入口验证能从原始输入重建主要结果；检查固定种子、依赖和输出一致性。打开 / 渲染最终 PDF，检查字体、公式、截断、图表清晰度和页数。

**验收**：代码、中文稿、英文源文件及 PDF 可打开；主要计算可重复；所有原题问题有回答或明确证据不足的解释；输入未变；页面和结论核对通过。

## 14. 检查和异常处理

| 检查 | 要防止的问题 | 不通过时的处理 |
|---|---|---|
| 输入哈希与路径 | 改写源文件、引用错数据 | 找出差异，从保留来源恢复副本并重新校验，不继续计算 |
| 奖牌与映射核对 | 团体奖牌膨胀、国家连接丢失 | 保留异常行，修正映射或降低项目层结论强度 |
| 时间来源检查 | 用未来信息预测历史 | 重建特征和切分，重跑受影响验证 |
| 模型与基线比较 | 复杂模型无实际收益 | 使用证据更稳的简单方案，保留比较结果 |
| 分布和区间约束 | 负牌、金牌多于总牌、概率错误 | 修正生成模型，不仅修改展示数字 |
| 2028 情景检查 | 缺失项目被假装已知 | 明确基准及扰动范围，报告情景结果 |
| 教练论断检查 | 残差被写成因果贡献 | 改为候选证据 / 条件情景，说明无法识别的部分 |
| 论文数字与页面 | 结果不一致、超页、公式 / 字体损坏 | 从结果重新生成表图并修正排版 |

不设置凭空的“误差必须小于某数”或“模型必须超过基线某百分比”。验收标准是比较方法合理、结果真实、局限明确；性能目标应在看到基线后另行讨论，不能通过挑测试样本达到。

## 15. 推进节奏与完成定义

建议先按以下检查点推进，不把训练排程当作比赛官方时限：

1. 检查点 A：环境和数据审计完成，能得到可信国家届次表。
2. 检查点 B：基线与至少一个主模型完成历史回测，能判断误差与区间是否可靠。
3. 检查点 C：2028 和首牌预测完成，所有未来假设明确。
4. 检查点 D：项目、教练和原创洞见回应完整，稳健性完成。
5. 检查点 E：代码、结果、论文及 PDF 检查通过。

在独立项目内可持续推进常规计算，不需要每一步重新确认。只有题目约束无法协调、必须改变用户要求，或外部条件确实阻止继续时才向用户说明；同时完成不受影响部分。

**“完成 C 题”的定义：** 有实际运行证据；所有子问题有可追踪回答；存在可重复运行入口；结果和论文一致；未来情景与教练限制已披露；英文论文 PDF 与可编辑源文件均可用。仅有计划、代码草稿或几张曲线均不算完成。
